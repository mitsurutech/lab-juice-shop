# Docker Compose の OWASP Juice Shop ラボ：わざと脆弱なオンラインショップを攻撃して Web アプリケーションのセキュリティを学ぶ

[English](README.md) | [Français](README.fr.md) | [日本語](README.ja.md) | [Español](README.es.md)

[![check](https://github.com/mitsurutech/lab-juice-shop/actions/workflows/check.yml/badge.svg)](https://github.com/mitsurutech/lab-juice-shop/actions/workflows/check.yml)

授業でそのまま使える **Web アプリケーションセキュリティのラボ**です。[MitsuruTech ラーニングプラットフォーム](https://mitsurutech.co.uk/ja/learning)が提供するもので、学校では生徒ごとに専用のデータベース、コンテナー、ターミナルをブラウザーで使えます。生徒は一人ひとり **OWASP Juice Shop** の専用コピーを受け取ります。Juice Shop は、わざと脆弱に作られたオンラインショップで、[OWASP Top 10](https://owasp.org/www-project-top-ten/)にわたる約100のチャレンジがあります。インジェクション、認証の不備、アクセス制御の不備、クロスサイトスクリプティング、セキュリティの設定ミスなどです。生徒は弱点を見つけ、**なぜそれが成り立つのか、コードをどう書くべきだったのかを説明**し、証拠を提出します。何もインストールせず、ほかの誰かのマシンに危険が及ぶこともありません。

`docker-compose` ファイル `compose.yaml` 1つだけで、自分のマシンでもプラットフォームでも同じように動きます。プラットフォームでは、生徒ごとにインターネットへの出口がない専用のコピーが用意されます。

## 守るべきルールは1つ

**攻撃してよいのは自分のコピーだけです。** このラボのすべては、インターネットにも他の生徒にも経路がない自分専用のコピーの中で動くので、届くのはラボが起動したアプリケーションだけです。自分のものではない Web サイト、ネットワーク、マシンに対しては、ラボの中でもそれ以外でも、決してツールを向けないでください。英国では[Computer Misuse Act 1990](https://www.legislation.gov.uk/ukpga/1990/18/contents)により犯罪となり、多くの国に同様の法律があります。弱点の仕組みを学ぶことは、弱点のないソフトウェアを作ることにつながります。授業の最初の話題には、このルールがなぜあるのかと、責任ある開示とは何かがふさわしいでしょう。

## 中身

| サービス | イメージ | メモリ | 内容 |
| --- | --- | --- | --- |
| `juice-shop` | [`bkimminich/juice-shop:v20.3.0`](https://hub.docker.com/r/bkimminich/juice-shop) | 512 MB | ポート 3000 で動くショップ。権限のないアカウント（ユーザー 65532）で、capability なしで動きます |

数秒で起動し、軽く使っているときは約 100 MB を使います。クラスで盛んに使うと、それ以上になります。

イメージはサードパーティ製のプログラムで、各プロジェクトが公開している公式イメージを改変せずに実行し、バージョンを固定しています（`latest` は使いません）。そのため、授業の途中でレッスンごとにラボが変わることはありません。ここでは何もビルドせず、このリポジトリのものはイメージに含まれません。

## プラットフォームで使う

[MitsuruTech ラーニングプラットフォーム](https://mitsurutech.co.uk/ja/learning)では、生徒ごとにラボの専用コピーがブラウザーで使え、横にターミナルも付きます。

**試すには：** [コンテナーのページ](https://mitsurutech.co.uk/ja/container)を開き、**サンプルラボ**からこのラボを探して「起動」を押します。試すだけならアカウントは不要です。

**クラスの課題として出すには：**

1. モジュールで種類が**ラボ**の課題を作り、**GitHub リポジトリ**を選びます。
2. `https://github.com/mitsurutech/lab-juice-shop` とブランチ `main` を指定します。compose ファイルは既定の `compose.yaml` です。ファイルを変えたいときは、先にリポジトリをフォークしてください。
3. 公開します。各生徒のコピーは公開したコミットから始まるので、あとでここを変更しても、すでに出したラボは変わりません。
4. 課題に何を提出するかを書き（[教員向け](#教員向け)を参照）、ほかの課題と同じように配布します。

マニュアルの[セキュリティラボのガイド](https://mitsurutech.co.uk/ja/help/security-labs)と[コンテナーラボのガイド](https://mitsurutech.co.uk/ja/help/labs)に、そのほかの説明があります。compose ファイルに書けること、1つのコピーに割り当てられるメモリ、教員が生徒のコピーを開いて確認し採点する方法などです。

学校のアカウントがまだありませんか。[最初の1年は無料](https://mitsurutech.co.uk/ja/pricing)で、生徒50人まで使えます。[登録](https://mitsurutech.co.uk/ja/signup)にはメールアドレスだけが必要です。

## 自分のマシンで動かす

Docker と Compose プラグインが必要です。初回の起動ではイメージをダウンロードします。

```bash
docker compose -f compose.yaml -f local.yaml up
```

ショップは <http://localhost:3000> を開きます。

`local.yaml` はポートを `127.0.0.1` だけに公開するので、ラボには自分のコンピューターからだけアクセスでき、ほかからは届きません。`Ctrl-C` で停止し、`docker compose -f compose.yaml -f local.yaml down -v` で削除します。アプリケーションは意図的に脆弱なので、攻撃用に使ってもよいマシンで動かしてください。

## 進め方

1. **ショップを開く**（プラットフォームでは、ラボのページで**開く**を押します）。客になったつもりで見て回ります。登録し、カゴに商品を入れ、レビューを読みます。
2. **Score Board を見つける。** Score Board は、すべてのチャレンジを難易度別に一覧にし、解けると緑になります。どこからもリンクされておらず、見つけること自体が最初のチャレンジです。
3. **難易度を上げていく。** チャレンジは OWASP Top 10 にわたります。インジェクション、認証の不備、アクセス制御の不備、クロスサイトスクリプティング、セキュリティの設定ミスなどです。ブラウザーが送受信する内容を見て、ページ自身のコードが何をしているかを読み、入力ごとにプログラムが何を信用しているかを考えます。Score Board のヒントはさらに踏み込んでいて、先に自分で試した生徒のほうがそこから多くを学べます。
4. **続きから再開できるようにする。** ラボを停止するとショップの状態は消えるので、明日も続ける生徒は、Score Board が表示する**継続コード**（continue code）をコピーしておきます。

## 教員向け

このラボには自動採点はありません。生徒が証拠を提出し、教員がほかのラボと同じように採点します。

**証拠は2つに分けて求めます。** 1つ目は作業の証拠です。Score Board で解いたチャレンジのスクリーンショット。ブラウザーにラボ自身のアドレスが写っていて、その生徒のコピーだとわかるものを求めます。2つ目は理解の確認です。それぞれについて、弱点が何か、使った入力そのものとそれが成功した理由、攻撃者がそれで何をできるか、コードをどう書くべきだったかを、自分の言葉で書いた説明で求めます。後者を見れば、理解したのか、解説記事の写しなのかがわかります。より高い水準を求めるなら、攻撃だけでなく修正も求めてください。

**コースのどこに合うか。** Juice Shop は、現実的なアプリケーションで OWASP Top 10 を学ぶのに向いています。脅威と脆弱性、インジェクション、認証とセッションの弱点、アクセス制御、暗号の失敗、セキュリティの設定ミス、そして方法としての脆弱性評価です。ユニットの法律と倫理の面、つまり許可と範囲、Computer Misuse Act 1990、責任ある開示にも役立ちます。正確な文言は、お使いの認定団体のユニットで確認してください。ここでは引用していません。

**誰が何を見られるか。** このようなラボは16～17歳の生徒に使われることが多くあります。コピーは起動した生徒だけのものです。そのモジュールを教える教職員は、生徒が何をしたかを見るためにコピーを開けます。生徒の作業を開いた記録はアクセスログに残り、生徒も読めます。

## ラボで動かないこと

一部のチャレンジはインターネットや AI サービスを必要とし、出口のないラボでは解けません。ショップの状態はメモリに保持されるので、ラボを停止すると消えます。続けるには継続コードを使ってください。512 MB を割り当てています。

## トラブルシューティング

- **起動した直後にショップが開かない。** 数秒待ってからもう一度「開く」を押してください。ラボは、ショップが応答して初めて準備完了と表示します。
- **自分のマシンでポート 3000 がすでに使われている。** `local.yaml` の左側の番号を、たとえば `127.0.0.1:3001:3000` のように変えて、そのポートを開いてください。
- **チャレンジがインターネットを必要とする。** ここでは解けません。仕様です。

## ラボのチェック

`test/check.sh` は、プラットフォームのランナーが各サービスを起動するのと同じ方法（すべての capability を外す、`no-new-privileges`、プロセス数の上限、メモリの上限、インターネットへの出口なし）でラボを起動し、このページが約束していることをネットワークの内側から確認します。Docker が必要で、push のたびに実行されます。ページの上部のバッジがそれです。

```bash
test/check.sh
```
